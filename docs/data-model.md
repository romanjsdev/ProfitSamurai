# Модель данных

Служебная база — реестр. У каждого клиента своя физическая база в том же кластере Postgres.

Имена колонок реестра совпадают с полями SQLAlchemy в `src/profitsamurai/db/service/models.py`. Кампании внутри базы клиента описаны в `src/profitsamurai/db/tenant/models.py`.

## База `profitsamurai_service`

Служебная база. Контейнер Postgres создаёт её при первом старте (`POSTGRES_DB`). Единственная служебная ревизия — `001_registry`: она явно создаёт `clients`, `client_databases` и `shops`. Клиентские базы накатывает отдельная ревизия `001_tenant`.

Подключение приложения: `DATABASE_URL`, драйвер `postgresql+asyncpg`.

### Таблица `clients`

Один ряд — одна компания-продавец. Это не кабинет Маркета и не учётная запись менеджера.

| Поле | Тип в Postgres | Зачем |
| --- | --- | --- |
| `id` | `uuid`, первичный ключ | Идентификатор клиента. Из него вычисляется имя его базы. |
| `name` | `text`, не NULL | Название компании, как его задали при регистрации. |

### Таблица `client_databases`

Один ряд — физическая база этого клиента.

| Поле | Тип в Postgres | Зачем |
| --- | --- | --- |
| `client_id` | `uuid`, первичный ключ, внешний ключ на `clients.id`, `ON DELETE CASCADE` | Чья это база. |
| `database_name` | `text`, не NULL, уникальное | Имя базы в кластере: `client_` и 32 шестнадцатеричных символа id. Пароль здесь не хранится. |
| `status` | `text`, не NULL | `provisioning`, `ready` или `failed`. Повтор использует то же имя и не удаляет базу. |

### Таблица `shops`

Один ряд — одно подключение маркетплейса у клиента. Сейчас маркетплейс только `yandex_market`.

| Поле | Тип в Postgres | Зачем |
| --- | --- | --- |
| `id` | `uuid`, первичный ключ | Идентификатор подключения. |
| `client_id` | `uuid`, не NULL, внешний ключ на `clients.id`, `ON DELETE CASCADE`, индекс | Компания, которой принадлежит магазин. |
| `marketplace` | `text`, не NULL | Код маркетплейса. Вместе с `business_id` уникален внутри клиента. |
| `business_id` | `bigint`, не NULL | Кабинет Маркета (`business.id`). |
| `api_key_ciphertext` | `bytea`, не NULL | Api-Key этого подключения, зашифрованный Fernet. |
| `connection_status` | `text`, не NULL | `connected`, если кампании записаны в базу клиента. `error`, если запись в неё не удалась. |

## База клиента `client_<hex>`

Создаётся отдельно. Схему накатывает `alembic.tenant.ini`, ревизия `001_tenant`. Объекты принадлежат роли `profitsamurai_app`.

Схемы `raw`, `ref` и `analytics` создаёт ревизия `001_tenant`. Роль `profitsamurai_datalens` может подключиться только при статусе `ready` и читать только `analytics`.

Ревизия `002_finance` добавляет в `raw` журнал импорта финансовых отчётов. Повтор того же периода создаёт новую версию и не удаляет предыдущую. Ревизия `003_file_sha` добавляет SHA-256 исходных байтов файла. Для уже лежащих файлов хеш считается по `content` и сами байты не меняются.

Ревизия `004_analytics_realization` добавляет `analytics.import_exclusions` и представления `analytics.selected_import`, `analytics.realization_suppressed_duplicate`, `analytics.realization_delivered`, `analytics.realization_transferred`, `analytics.realization_returned`, `analytics.realization_unredeemed`. Выбор версии смотрит на статус `done`, время `finished_at` и активное исключение. Миграция сама не исключает импорты. Вторую строку соседней одинаковой пары в октябрьской реализации версий 2–4 скрывает отдельное представление. Роль DataLens эти объекты только читает. Лист `lost_items` остаётся в `raw`.

Ревизия `005_analytics_services` добавляет `analytics.service_sku_charge`, `analytics.service_order_charge`, `analytics.netting_movement`, `analytics.bank_order` и `analytics.bank_order_conflict`. Все читают уже выбранный импорт. Услуга со строковым `shopSku` попадает в первое представление, строка без него — во второе. Сумма берётся из одного поля листа. Движение взаимозачёта хранит `transactionSum` и повторенный `bankSum` строки; поручение показывает сумму один раз и только если внутри номера она одна. Расхождение суммы, даты или статуса остаётся в диагностическом представлении. Прибыль эти представления не считают.

Попытка со статусом `failed` может хранить ZIP и строки, если обрыв случился после их записи. `row_count` тогда равен числу сохранённых строк, а не нулю. Пока импорт магазина держит advisory lock, строки `running` не переводятся в `failed`: журнал не знает, какая из них принадлежит живой задаче. Когда замок свободен, явный вызов восстановления помечает брошенные `running` как `failed`, проставляет фактический `row_count` и не удаляет файл, строки и не запускает новый импорт. Длительность попытки сама по себе признаком зависания не является.

### Таблица `raw.report_imports`

Одна строка — одна попытка загрузить один отчёт.

| Поле | Тип в Postgres | Зачем |
| --- | --- | --- |
| `id` | `uuid`, первичный ключ | Идентификатор попытки. |
| `shop_id` | `uuid`, не NULL | Магазин из реестра. Внешнего ключа нет: реестр лежит в другой базе. |
| `business_id` | `bigint`, не NULL | Кабинет Маркета. |
| `report_type` | `text`, не NULL | `goods_realization`, `marketplace_services` или `united_netting`. |
| `period_from`, `period_to` | `date`, не NULL | Календарный месяц, включительно. |
| `campaign_id` | `bigint`, NULL допустим | Кампания для отчёта реализации. Для двух других отчётов пусто. |
| `yandex_report_id` | `text`, NULL допустим | Идентификатор генерации в Маркете. Ссылка на файл сюда не пишется. |
| `status` | `text`, не NULL | `running`, `done`, `no_data`, `too_large` или `failed`. |
| `version` | `integer`, не NULL | Номер версии импорта этого магазина и периода. |
| `started_at` | `timestamptz`, не NULL | Начало попытки. |
| `finished_at` | `timestamptz`, NULL допустим | Окончание попытки. |
| `row_count` | `integer`, не NULL | Сколько строк разобрано. |
| `error_message` | `text`, NULL допустим | Короткий текст ошибки без ключа и без ссылки на файл. |

### Таблица `raw.report_files`

Оригинальный скачанный файл без изменений.

| Поле | Тип в Postgres | Зачем |
| --- | --- | --- |
| `id` | `uuid`, первичный ключ | Идентификатор файла. |
| `import_id` | `uuid`, не NULL, уникальный, внешний ключ на `raw.report_imports.id` | К какой попытке относится файл. |
| `content` | `bytea`, не NULL | Байты файла. |
| `byte_size` | `integer`, не NULL | Размер `content`. |
| `content_sha256` | `text`, не NULL | SHA-256 байтов `content`, 64 шестнадцатеричных символа в нижнем регистре. |

### Таблица `raw.report_rows`

| Поле | Тип в Postgres | Зачем |
| --- | --- | --- |
| `id` | `uuid`, первичный ключ | Идентификатор строки. |
| `import_id` | `uuid`, не NULL, внешний ключ на `raw.report_imports.id`, индекс | К какой попытке относится строка. |
| `sheet` | `text`, не NULL | Имя листа внутри архива. |
| `row_number` | `integer`, не NULL | Порядковый номер внутри попытки. |
| `payload` | `jsonb`, не NULL | Строка отчёта как есть, без фиксированного набора колонок. |

### Таблица `ref.campaigns`

Один ряд — одна кампания магазина этого клиента.

| Поле | Тип в Postgres | Зачем |
| --- | --- | --- |
| `campaign_id` | `bigint`, первичный ключ | Идентификатор кампании в Маркете. |
| `business_id` | `bigint`, не NULL, индекс | Кабинет, к которому кампания относится. |
| `placement_type` | `text`, NULL допустим | Значение официального поля `placementType` (`FBS`, `FBY`, `DBS` и другие). Пустое, если Маркет его не прислал. |
