Дата: 2026-11-04. Исследование. Код, база, `LESSONS.md`, ADR, `ROADMAP.md`, `.cursor/agents/`, `.cursor/rules/`, `agent-workflow.md` и финансовые заметки не менялись. Повторный импорт не запускался. ZIP в `support-attachments/` не перепаковывались.

## 1. Краткий итог

Три открытых вопроса сверены с исходными ZIP/JSON и официальными страницами.

1. **`transactionId`.** Ключ в файле есть у всех строк. Значение — JSON `null`. Ранняя фраза «файл содержит `transactionId`» и поздняя «значение пустое» описывают один и тот же факт, а не разные отчёты.
2. **Премия 883,32.** Строка найдена в оригинальном сентябрьском ZIP взаиморасчётов. `bonusAccountYearMonth` у неё `null`. По документации и этой строке месяц премии как период признания не определяется. Ноль по группам `2026-09` не равен 883,32 и связь с остатком баллов не доказывает.
3. **Заказ `61947964226`.** В октябрьском `delivered` лежит с доставкой `05.10.2026` и передачей `30.09.2026`. Строгое чтение справки «и передача, и доставка в этом периоде» с этой строкой не сходится. Другие чтения справки и молчание страницы метода противоречием не закрываются. Универсальное правило выручки из одного заказа не следует.

Субагенты `market-api-expert` и `marketplace-analytics-expert` в этом прогоне **не ответили**: вызов Task оборвался лимитом среды. Контракт API и строки проверил главный агент сам. Раздел 5 поэтому без ответов специалистов.

## 3. Проверка премии 883,32 и `bonusAccountYearMonth`

### Первоисточник строки

Оригинальный ZIP сентября, report `4114316c-9159-42f2-9df6-3d5393f4b728`, лист `transaction_date.json`, объект № 1752.

Поля строки:

| Поле | Значение |
| --- | --- |
| `transactionSource` | `Премия` |
| `offerOrServiceName` | `Денежная премия за участие в совместных акциях` |
| `transactionType` | `Начисление` |
| `transactionSum` | `883.32` |
| `transactionDate` | `31.08.2026 00:00` |
| `paymentStatus` | `Переведён по графику выплат` |
| `bonusAccountYearMonth` | `null` |
| `bankOrderId` | `208852` |
| `bankOrderDate` | `14.09.2026` |
| `bankSum` | `60022.01` |
| `transactionId` | `null` |
| `orderId` / `shopSku` / `actId` | `null` |

В поручении `208852` в том же файле 665 строк. Сумма их `transactionSum` равна `60022.01`, то есть `bankSum` на строке премии — сумма всего поручения, не сумма одной премии.

Другой строки с суммой 883,32 в сентябре версии 1 нет. Августовского отчёта в базе нет.

### Документация поля

Та же страница `generateUnitedNettingReport`, 2026-11-04, `r21924375`.

- Лист `transaction_date`: `bonusAccountYearMonth`, тип `string`, подпись «Расчётный период премии за участие в совместных акциях».
- Лист `netting_bonuses`: то же JSON-имя, подпись «Месяц формирования премии за участие в совместных акциях».
- Формата `YYYY-MM` страница не задаёт.
- Правила, что строка источника «Премия» должна заполнять поле, нет.
- Период запроса отчёта задаётся `dateFrom` / `dateTo` (или другими типами запроса). Это не то же самое, что колонка `bonusAccountYearMonth`.

Справка [Баллы Маркета](https://yandex.ru/support/marketplace/ru/accounting/market-points), чтение 2026-11-04, индекс кабинета `r21931970`: неиспользованный остаток на конец месяца перечисляется премией и показывается в отчёте агента строкой «Премия, предоставленная Исполнителем». Колонку `bonusAccountYearMonth` справка не определяет. Доходом продавца в формуле прибыли строку баллов или премию не называет.

### Арифметика групп `2026-09` в том же файле

По сентябрьскому netting версии 1, источники баллов и акций:

| `bonusAccountYearMonth` | Источник | Статус | Строк | Сумма |

| `2026-09` | Баллы за скидку Яндекс Плюс | пополнен баланс | 4 | 680 |
| `2026-09` | Возврат баллов за скидку Маркета | списан с баланса | 2 | −1234 |
| `2026-09` | Скидка за участие в совместных акциях | списан с баланса | 306 | −72807 |
| `2026-09` итог |  |  |  | **0** |
| `<empty>` | Премия | Переведён по графику выплат | 1 | 883.32 |

Итог групп с `bonusAccountYearMonth = 2026-09` равен нулю и не равен 883,32. Значения `2026-08` в этом поле нет.

| Утверждение | Статус |
