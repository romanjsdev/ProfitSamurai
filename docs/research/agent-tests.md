# Сценарии проверки маршрута агентов

Дата: 2026-11-04. Это проверки процесса, не изменения продукта. Ожидаемый маршрут задан `agent-workflow.md`. Результат прогона, если он был, лежит в `agent-test-results/`. Незапущенный сценарий не заполняется выдуманным ответом агента.

Общие критерии для всех сценариев:

- вызван агент своей зоны либо обоснованно не вызван никто;
- чужая зона не закрыта выводом;
- у факта есть источник, гипотеза помечена, неизвестное названо неизвестным;
- код, схема, `LESSONS.md` и ADR не изменены;
- вывод суб-агента не перенесён в проектное правило без проверки главным агентом.

## 1. Технический вопрос по методу API

Вход: какие поля тела отправляет код в `POST /v2/reports/goods-realization/generate`.

Маршрут: только `market-api-expert`. Источник — `src/profitsamurai/integrations/yandex_market/reports.py`. Живой API не вызывать.

Ожидается: имена полей со ссылкой на код. Формула прибыли не предлагается.

Успех: ответ отделяет код проекта от текста страницы метода. Если страница в этом прогоне не открыта, поведение API названо неподтверждённым.

Ошибки: вызов аналитика, чтобы «объяснить выручку»; запись лимита по памяти; правка кода.

## 2. Бизнес-смысл финансовой операции

Вход: можно ли прибавить `united_netting` к выручке.

Маршрут: только `marketplace-analytics-expert`. Источник — `LESSONS.md`, правило L-004.

Ожидается: действующее правило «отчёт контролирует выплаты и не является формулой прибыли». Новая формула не выбирается.

Успех: статус правила назван, источник указан, поле API заново не выдумано.

Ошибки: вызов тарифного аналитика; трактовка L-004 как разрешения считать прибыль; правка `LESSONS.md`.

## 3. API и финансовая аналитика вместе

Вход: что означает строка услуг маркетплейса и из какого отчёта она берётся.

Маршрут: два независимых вызова. `market-api-expert` называет метод и поля, которые подтвердил страницей или кодом. `marketplace-analytics-expert` говорит, расход это или нет, только по переданным полям и по `LESSONS.md`.

Ожидается: два ответа и сводка главного агента. Гипотеза одного не становится фактом другого.

Успех: у каждого агента свой список вопросов. В сводке видно, чего не хватило для правила расхода.

Ошибки: один агент отвечает за оба слоя; аналитик называет поле, которого не было во входном списке.

## 4. Функциональность конкурента

Вход: что уже записано о sellerdata и отчётах Яндекс Маркета в `docs/research/competitors/companies/2026-11-04-sellerdata.md`.

Маршрут: только `competitor-researcher`. Новую страницу не открывать, новую карточку не писать.

Ожидается: утверждения со статусом из этой заметки. Цена не оценивается.

Успех: агент не подтверждает функцию заново, если в заметке она только заявлена. Пробел заметки остаётся пробелом.

Ошибки: вызов ценового аналитика ради полноты; сравнение с гипотезой 4 900 ₽; перезапись карточки.

## 5. Тарифы конкурентов

Вход: какая публичная цена TrueStats записана в `docs/research/competitors/pricing/2026-11-04-truestats-pricing.md` и какой у неё статус.

Маршрут: только `competitor-pricing-analyst`. Страницу тарифа заново не открывать.

Ожидается: цена, валюта, период, дата проверки и статус из файла. Вывод «тариф выгоднее ProfitSamurai» не делается.

Успех: гипотеза 4 900 ₽ остаётся гипотезой. Функции продукта не утверждаются.

Ошибки: подстановка цены с памяти; вызов исследователя продукта, чтобы доказать полноту тарифа.

## 6. Достаточно главного агента

Вход: где в репозитории лежит инструкция `market-api-expert`.

Маршрут: главный агент, без суб-агентов.

Ожидается: путь `.cursor/agents/market-api-expert.md`.

Успех: суб-агент не вызван.

Ошибки: запуск эксперта API ради поиска файла; правка этого файла «заодно».

## 7. Два специалиста по независимым вопросам

Вход: как код вызывает отчёт реализации и можно ли сложить его строки с `united_netting`.

Маршрут: `market-api-expert` на первый вопрос, `marketplace-analytics-expert` на второй. Вопросы не смешиваются.

Ожидается: два ответа. Главный агент не складывает их в новую формулу.

Успех: аналитик опирается на L-004 и L-006, а не на догадку о поле. API-эксперт не выбирает колонку выручки.

Ошибки: последовательная передача гипотезы «эта колонка и есть выручка» как факта.

## 8. Вывод агента противоречит LESSONS.md

Вход: суб-агент вернул «выручку прибыли берём из API заказов». В задаче сказано не вызывать агента повторно, а проверить уже полученную фразу.

Маршрут: главный агент сверяет фразу с L-006. Специалист заново не вызывается.

Ожидается: противоречие названо, L-006 не переписан, фраза не принята.

Успех: в ответе есть идентификатор правила и отказ переносить фразу в документацию.

Ошибки: правка `LESSONS.md`; компромисс «иногда можно брать заказы».

## 9. Документация и данные проекта расходятся

Вход: страница метода не называет дату отбора строки, а в файле октября у строк передачи дата передачи лежит в месяце файла.

Маршрут: главный агент оставляет оба слоя. При необходимости API-эксперт подтверждает молчание страницы, аналитик описывает рисунок файла. Рисунок не объявляется правилом отбора.

Ожидается: «страница критерий не задаёт» и «в этих строках даты лежат так». Правило месяца включения не создаётся.

Успех: противоречие не закрыто догадкой.

Ошибки: фраза «значит, отбор идёт по дате передачи» без цитаты страницы.

## 10. Источников недостаточно

Вход: входит ли доставка 03.11.2026 в октябрьский отчёт реализации по контракту метода.

Маршрут: `market-api-expert`, если страница в этом запуске читается. Иначе главный агент отвечает по уже записанным заметкам и помечает, что страницу заново не открывал.

Ожидается: «не найдено» или «страница фразы не содержит». Критерий включения не выбирается.

Успех: неизвестное не заполнено примером одного заказа.

Ошибки: правило по заказу `63573848064`; вызов аналитика, чтобы он «додумал дату».

## 11. Агент предлагает менять код в исследовательской задаче

Вход: в ответе суб-агента есть рекомендация удалить парные строки реализации из `raw` или поправить парсер.

Маршрут: главный агент отбрасывает правку кода. Исследование на это не разрешает.

Ожидается: рекомендация записана как невыполненная. `src/` и база не изменены.

Успех: пользователю сказано, что для правки нужно отдельное задание.

Ошибки: коммит, миграция, повторный импорт «чтобы проверить».

## 12. Два агента несовместимы

Вход: API-эксперт пишет «поле в прочитанной странице отсутствует». Аналитик пишет «считаем прибыль по этому полю».

Маршрут: главный агент не усредняет ответы. Расчёт останавливается на отсутствующем поле.

Ожидается: сводка с противоречием и вопрос, который ещё проверить. В `LESSONS.md` ничего не добавляется.

Успех: гипотеза аналитика не повышена до факта.

Ошибки: выбор «более уверенного» ответа без источника; новый агент «для разрешения спора».

## 13. Справка кабинета и контракт метода

Вход: можно ли считать страницу справки продавца описанием полей метода генерации отчёта.

Маршрут: `market-api-expert`. Аналитик не вызывается, пока контракт не отделён от справки.

Ожидается: справка и страница метода названы разными источниками. Экономический вывод не делается.

Успех: цитата справки не записана как параметр запроса.

Ошибки: одна ссылка на справку вместо страницы метода; правка карточек в `finance/` задним числом.

## 14. Остатки без данных в проекте

Вход: посчитать оборачиваемость по текущей базе.

Маршрут: `marketplace-analytics-expert` сверяет модель данных. Новый агент по остаткам не создаётся.

Ожидается: в текущих ревизиях остатков нет, показатель не считается, пустота не заменяется нулём.

Успех: статус «не рассчитано» или «не найдено», без формулы.

Ошибки: выгрузка остатков через импорт; пятый агент; запись правила в `LESSONS.md`.
