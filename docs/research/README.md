# Исследования

Здесь хранится история проверок, на которые опираются два суб агента. Заметка описывает, что было известно в день исследования. Она не меняет код, схему базы и действующие правила продукта.

## Кто пишет

| Каталог | Суб агент | Область |
| --- | --- | --- |
| `market-api/` | `market-api-expert` | Методы, поля, лимиты, статусы и изменения API Яндекс Маркета |
| `marketplace-analytics/` | `marketplace-analytics-expert` | Смысл операций, показатели, распределение расходов, возвраты и правила прибыли |

Инструкции агентов лежат в `.cursor/agents/`. Формат заметок каждого направления описан в `README.md` этого каталога. Общие правила, которые учитывают оба агента, лежат в [LESSONS.md](LESSONS.md). Это краткий справочник, а не копия всех заметок.

## Как обновляется общая база

1. Агент проводит исследование.
2. Подробный результат сохраняется новым файлом в тематической папке этого агента.
3. Агент выделяет выводы, которые важны для обоих агентов.
4. Агент предлагает изменение `LESSONS.md` со ссылкой на заметку и первичный источник. Сам справочник он не переписывает.
5. Основной агент Cursor проверяет предложение и отделяет подтверждённый вывод от гипотезы.
6. После проверки основная база обновляется. Старое правило при пересмотре остаётся в истории записи.

## Как заметки версионируются

- Одна проверка — один файл `YYYY-MM-DD-kratkoe-imya.md`.
- Файл после создания не переписывается новым результатом.
- Повторная проверка той же темы — новая заметка.
- Если новый вывод расходится со старым, новая заметка ссылается на предыдущую и объясняет, что изменилось.
- В заметку не кладут ключи, токены, пароли, шифротекст, подписанные URL, персональные данные, временные выгрузки и полные файлы отчётов.
- Каталоги `docs/research/` и `.cursor/agents/` отслеживаются Git. Исключений для них нет.

## Связь с архитектурой и решениями

Заметка не становится требованием к продукту. Действующие решения записаны в `docs/adr/` и `docs/data-model.md`. ADR [0001](../adr/0001-decisions-are-committed.md) требует хранить принятое решение в репозитории. ADR [0008](../adr/0008-client-database.md) фиксирует границу: сырые финансовые отчёты сохраняются, выручка и прибыль по ним пока не считаются.

Если исследование предлагает изменить бизнес-логику или архитектуру, предложение пишется отдельно внутри заметки: основания, альтернативы и последствия для расчётов и уже сохранённых данных. Код и ADR при этом не меняются. Утверждение оформляется новым ADR или правкой действующего документа отдельным заданием.
