# ADR 0003. Одна служебная база

## Статус

Принято

## Контекст

Дальше у каждого кабинета может появиться своя база: заказы и остатки живут на кампании, а деньги и отзывы — на кабинете. Для списка кампаний отдельная база на кабинет ничего не даёт. В ней нечего хранить, кроме тех же двух идентификаторов.

## Решение

Один экземпляр Postgres 16. Одна база `profitsamurai_service`, её создаёт контейнер. Схема — Alembic при старте API. Базы вида `shop_…`, провижининг `CREATE DATABASE` и второй каталог миграций отложены, пока не появится факт, который надо писать в базу кабинета.

## Последствия

`POSTGRES_ADMIN_URL` не нужен. API и Postgres — единственные сервисы Compose. Когда появится вторая база, это будет новый ADR, а не молчаливое возвращение старой схемы.
