# ADR 0002. Первый запрос — список кампаний

## Статус

Принято

## Контекст

Почти все методы Partner API адресуются либо кабинетом (`businessId`), либо кампанией (`campaignId`). Пока этих идентификаторов нет, заказывать отчёты и читать заказы не к чему.

`GET /v2/campaigns` с заголовком `Api-Key` возвращает кампании ключа и у каждой — `business.id`. Это первый запрос, после которого система знает, кого она синхронизирует.

## Решение

Единственный вызов Маркета в этом срезе — `GET https://api.partner.market.yandex.ru/v2/campaigns`. Его делает `POST /cabinets`: в теле Api-Key, в ответе список `{business_id, campaign_ids}`. Страницы читаются, пока `pager.pagesCount` не исчерпан. Редиректы не следуют, чтобы ключ не ушёл на другой хост. `420`, `429` и `5xx` повторяются, прочие `4xx` — нет.

`GET /cabinets/{business_id}` только читает уже записанные идентификаторы и Маркет не вызывает.

## Последствия

Заказов, каталога, остатков, денег, рекламы и отзывов в этом срезе нет. Воркер и очередь отчётов не запускаются. Повторный `POST /cabinets` — это синхронизация, поэтому ответ `200`, а не `201`.

Просмотр отчёта по товарам без записи описан в ADR 0007 и это ограничение снимает.
