# ADR 0006. Наш API закрыт одним bootstrap-токеном

## Статус

Принято

## Контекст

`POST /cabinets` принимает чужой Api-Key и кладёт его в базу. Без заслона любой, кто достучался до порта, может записать свой ключ или прочитать чужие `campaign_id`. Полноценные арендаторы, свои API-ключи и привязка «ключ → кабинеты» для одного запроса не нужны.

## Решение

Оба маршрута требуют заголовок `X-Bootstrap-Token`. Ожидаемое значение — `BOOTSTRAP_TOKEN`. Сравнение постоянное по времени. Пустой токен в настройках — ответ `503`, запрос к Маркету не уходит. Несовпадение — `401`.

## Последствия

Токен один на весь процесс. Это не разграничение кабинетов. Когда появится второй пользователь, нужен новый ADR и замена этого заголовка, а не рост таблицы `cabinets` полем «чей это токен».
