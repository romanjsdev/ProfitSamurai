# ADR 0002. Подключение магазина читает список кампаний

## Статус

Принято

## Контекст

Почти все методы Partner API адресуются кабинетом (`businessId`) или кампанией (`campaignId`). Пока этих идентификаторов нет, остальные данные Маркета читать не к чему.

`GET /v2/campaigns` с заголовком `Api-Key` возвращает кампании ключа. У каждой есть `business.id`. Поле `placementType` может отсутствовать.

## Решение

Единственный вызов Маркета — `GET /v2/campaigns`. Его делает `POST /clients/{client_id}/shops`: в теле Api-Key, в ответе список `{business_id, campaign_ids}`. Страницы читаются, пока `pager.pagesCount` не исчерпан, не больше 1000 страниц по 100 кампаний. Редиректы не следуют, чтобы ключ не ушёл на другой хост. `420`, `429` и `5xx` повторяются, прочие `4xx` — нет. Ошибка Маркета отвечает `502`.

Кампания без `business.id` пропускается. Если не осталось ни одного кабинета, ответ `422`, и в базу ничего не пишется. Один `campaign_id` принадлежит одному кабинету. При чтении страниц остаётся первое вхождение. Повторное подключение того же кабинета заменяет его набор кампаний в `ref.campaigns`: лишние строки этого `business_id` удаляются. Кабинет, которого больше нет в ответе ключа, сам не удаляется.

В реестр пишется строка `shops`: `business_id`, шифротекст ключа, `marketplace` `yandex_market` и `connection_status`. В базу клиента пишется `ref.campaigns`: `campaign_id`, `business_id` и `placement_type`. Сырой JSON, имя, домен и прочие поля ответа не сохраняются.

Клиент должен быть в статусе `ready`, иначе ответ `409`. Если кампании в базу клиента не записались, `shops.connection_status` становится `error`, а ответ — `502`.

## Последствия

Заказов, каталога, остатков, денег, рекламы и отзывов этот вызов не читает. Модель размещения хранится в `ref.campaigns` и берётся из `placementType`. Если Маркет поле не прислал, оно остаётся пустым.
